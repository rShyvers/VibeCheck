What does this machine
actually do?

Not a simulator you trust by reputation. A mathematical function — step : Program → State → StepResult — that says exactly what every one of 40 MIPS instructions does to registers, memory, and the program counter, with a machine-checked proof that it matches a written spec.

The machine, concretely

One instruction in, one new state out

step is a single pattern match over 40 instruction shapes. Every case is a few lines that say exactly what real MIPS32 hardware does — no simulator-specific shortcuts hiding inside.

step p s  =  match fetch p s.pc with
  | add rs rt rd  =>
      let sum := reg[rs] + reg[rt]
      if signedOverflow sum then halt .arithmeticOverflow
      else next { reg[rd] := sum, pc := pc + 4 }
arithmetic & logic — add, sub, mult, div, and/or/xor, slt shifts — sll, srl, sra memory — lw/sw, lb/lbu/sb, lh/lhu/sh control flow — beq, bne, blez, bgtz, j, jal syscall
What's actually proven

Not "it runs" — theorems about every path

21 theorems about step, each a precise claim checked for every input, not a handful of test cases. Three examples:

add_overflow_not_wrapped

A real CPU traps on signed overflow instead of silently wrapping. Proof: add on 0x7fffffff + 1 can never reach a next state — only halt.

zero_write_not_observable

Register $zero is hardwired. Proof: for any value written to it, reading it back is never that value.

beq_taken_spec

Branch targets follow the MIPS rule exactly: PC_next + (offset << 2), proven equal to what step actually computes.

How we know, not just assert

Checked by the kernel. Checked against reality.

Two proof gates

lake check replays every proof through Lean's own kernel — one unfinished step anywhere fails it. lake comparator checks a named 8-theorem surface against a trusted config, one claim from each kind the spec makes.

Allowed axioms, both gates: propext, Classical.choice, Quot.sound. Nothing else — no silent sorry.

A real simulator as oracle

MARS 4.5 is the test environment, never the spec. 12 self-written programs covering the full instruction set run through both the Lean interpreter and real MARS.

12/12 agree.

Finding a real bug

The verification caught a planted bug

An equivalence corpus pairs direct arithmetic against bit-shift "optimizations" — the kind of strength reduction a compiler would do. Two of seven pairs are deliberately wrong, so the harness has to catch a real divergence, not just confirm agreement everywhere.

div_pow2_buggy:  x/4 via div/mflo  vs  plain sra by 2
  input = -1  →  base = 0,  variant = -1   caught

mod_pow2_buggy:  x%4 via div/mfhi  vs  plain andi mask
  input = -1  →  base = -1, variant = 3   caught

Classic bugs: shifting a negative dividend rounds toward −∞, not zero; masking a negative remainder is always non-negative. Real divergences a naive "looks equivalent" check would miss — found because the proof has to hold for every signed 32-bit input, not just the ones a human thought to try.

The demo — Tic-Tac-Toe

We didn't write a verified game.
We wrote MIPS.

The whole board packs into one register, 2 bits per cell. "Does X have three in a row?" is one and + beq against a precomputed mask — the exact same two instructions this deck already showed kernel-checked theorems about.

li   $t9, 21        # cells (0, 1, 2), as X
and  $t0, $s0, $t9
beq  $t0, $t9, x_wins   # every bit of the mask is set → X owns this line

What's proven

Every and/beq/ or/sll this program runs has a kernel-checked theorem saying what it does — the same trust chain as the rest of this deck, not a special case for the game.

What's tested, not proven

The specific sequence of those instructions that makes this a correct tic-tac-toe engine has no Lean proof of its own — it's checked exhaustively instead: 34,529 board/move combinations, 775 full games, zero failures. We say so in the demo itself.

What's next

The semantics grew fast; one gap remains

Landed since this deck started

  • Real branch delay slots, jr/jalr (real subroutine calls), floating point, exceptions/traps
  • 145 kernel-checked theorems, up from ~12 with real coverage
  • A false theorem statement found and fixed before it could mislead anyone

Still missing: assembler macros

The one specific, unresolved blocker for unsealing a real hand-written buggy program and proving a surgical fix — everything else that was "out of scope" is now real.

Not re-pinning yet, on purpose: delay slots would silently break the shipped Tic-Tac-Toe engine (checked directly — 18,356 failures against the new semantics). Connect Four is next in line once that rewrite happens.
