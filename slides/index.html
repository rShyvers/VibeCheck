The story

Spec → proof → real bug → browser

We didn't verify a toy. We built small-step MIPS semantics in Lean, proved it matches a written spec, checked that spec against a real simulator on an independent test corpus — then used exactly that machinery to catch two deliberately planted arithmetic bugs before they could pass as correct.

Verification

Two gates decide what "done" means

lake check

Rebuilds the default target and replays it through Lean's own kernel. All-or-nothing: one unfinished proof anywhere fails the whole gate.

Covers: Word, Types, State, Instruction, Asm, Step — a sorry-free Checked target.

lake comparator

Checks a named list of theorems against a trusted config, theorem-by-theorem — the right tool for a spec file that mixes finished and unfinished proofs.

8-theorem trusted surface, one from each kind of claim the spec makes: arithmetic, overflow, branch, jump, memory, bad-output rejection, invariant.

allowed axioms propext Classical.choice Quot.sound anything else — fails both gates

Finding a real bug

The verification caught a planted bug

An equivalence corpus pairs direct arithmetic against bit-shift "optimizations" — the kind of strength reduction a compiler would do. Two of seven pairs are deliberately wrong, so the harness has to catch a real divergence, not just confirm agreement everywhere.

div_pow2_buggy:  x/4 via div/mflo  vs  plain sra by 2
  input = -1  →  base = 0,  variant = -1   caught

mod_pow2_buggy:  x%4 via div/mfhi  vs  plain andi mask
  input = -1  →  base = -1, variant = 3   caught

Classic bugs: shifting a negative dividend rounds toward −∞, not zero; masking a negative remainder is always non-negative. Real divergences a naive "looks equivalent" check would miss — found because the proof has to hold for every signed 32-bit input, not just the ones a human thought to try.

What's next

v2 widens the semantics; the bug hunt isn't dropped

In progress — v2 ISA expansion

  • Real branch delay slots (MIPS32 hardware behavior, not MARS's simplification)
  • Minimal floating point (coprocessor-1)
  • Exceptions/traps (coprocessor-0)
  • Assembler macros — the missing piece for the real sealed program

Deferred, not dropped

The original plan: unseal a real, hand-written buggy MIPS program, find its arithmetic error with a functional-intent spec, prove a surgical fix. It needs assembler macros v1 doesn't have.

Once v2 lands them, the cleanroom protocol stays binding and the hunt resumes on the real program — the equivalence corpus stands as the interim proof the method works.
